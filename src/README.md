# Собственное приложение ZX19 — состояние разработки

Написаны независимые модули C11:
- watch_core — время событий, таймер с сохранением выбранной длительности, секундомер, меню, четыре UTF-8 сообщения, перерисовка по изменениям.
- watch_render — монохромный интерфейс, собственный bitmap-шрифт с кириллицей и латиницей; без framebuffer, heap, сглаживания и сетевых ресурсов.
- watch_input — касания, кнопка и изменение времени таймера.
- watch_lcd — протокол CASET/RASET/RAMWR, окно 172x320 с X-offset=34, поток RGB565 порциями максимум 64 байта. Нужен предварительно настроенный аппаратный транспорт с таймаутами.
- watch_touch — чтение CST816-совместимого контроллера: адрес 0x15, ChipID 0xA7, кадр 0x01 длиной 6 байт; касания на отпускании, свайпы, отмена незавершённого жеста. Нужен аппаратный I2C-адаптер.

CST816 определяется в штатном образе по чтению регистра A7 и сравнению с B4/B5/B6; собственный драйвер отвергает другие ID. Это статическая идентификация поддерживаемого семейства, а не реально считанный ID тача данного экземпляра. Корпус не вскрывался.

## Как посмотреть
Открыть ../ZX19-preview.html двойным щелчком. Файл автономный, без сервера и интернета. Его WebAssembly собран из тех же C-модулей; логика не переписана на JavaScript. Браузерная оболочка подаёт время, касания и тестовые сообщения. Это предпросмотр, не прошивка часов.

## Воспроизведение разработчиком
Из корня проекта:
1. tools/python/python.exe tools/build_core.py
2. tools/python/python.exe -m unittest discover -s tests -v
3. tools/python/python.exe tools/build_preview.py
4. tools/python/python.exe tools/check_preview_browser.py

Пакеты зафиксированы в tools/requirements-lock.txt. Браузерная проверка использует установленный Chrome и отдельный профиль в build, не меняет пользовательский профиль.

## Проверенное
43 успешных unit/integration/negative/boundary/regression проверки на Windows x64, с реальной компиляцией C в DLL и отдельные объекты Cortex-M4. WebAssembly запущен в Chrome при 980x850 и 360x800; проверены переходы через меню, запуск таймера, добавление сообщения и свайп к сообщениям. Дополнительно пройдены сценарии через синтетические pointer events браузера; это не физическое испытание тача.

Состояние ядра — 796 байт (четыре сообщения по 192 байта плюс счётчики и флаги). Это больше ранних 280 байт: очередь расширена, чтобы русское сообщение не обрывалось после 31 буквы. При превышении 191 байта отображается многоточие с сохранением границы UTF-8. Очередь хранится только в RAM, старейшее сообщение заменяется при заполнении.

Размещаемые секции пяти ARM-объектов — 6205 байт, включая рендер и шрифт. Это не окончательный размер прошивки и не полный расход RAM: startup, MMIO, Bluetooth, vendor runtime, стеки и память системы не включены.

## Что пока не реализовано
Startup и linker script конкретной платы, реальные GPIO/I2C/8080 транспортные функции, Bluetooth и уведомления с телефона, RTC/питание/зарядка/датчики, постоянное хранение, полный текстовый скролл длинного сообщения, медицинские и платёжные функции. Нельзя устанавливать .o, .dll, .wasm или HTML в часы.

## Адаптер заводских полос экрана

`watch_strip.c` выводит интерфейс в переданный буфер 172×10 RGB565 (3440 байт).
Дополнительного framebuffer и динамических выделений нет; ARM-секции адаптера
занимают 216 байт. Все 32 полосы каждого из пяти экранов сравнены с полной
отрисовкой попиксельно; проверены защитные значения вокруг буфера и неизменность
состояния. Это подготовка к найденному заводскому callback, а не установленный hook.

Заводская таблица из 210 callback находится по 0x865b24, выбранный callback —
в состоянии диспетчера по 0x20c9ac, вызов — 0x8397fe. Подтверждения:
`tools/inspect_display_dispatch.py` и `research/display-dispatch-map.json`.
Для кадра нужно зафиксировать время и состояние на все полосы. Адаптер повторяет
обход графических элементов для каждой полосы; фактическая скорость и расход
энергии на часах пока не измерены.

`tests/emulator.ld` задаёт только искусственную карту памяти для проверки ARM.
`build/emulator-only.elf` нельзя устанавливать на часы. Воспроизведение эмуляции:
установить тестовую зависимость `unicorn==2.1.4`, выполнить `tools/build_core.py`,
затем `tools/test_arm_execution.py`. Это проверка CPU, без периферии и vendor ROM.

Методы bus.read/command/data обязаны иметь конечные таймауты. При ошибке чтения тача адаптер платы должен вызвать watch_touch_cancel. При ошибке LCD его fault блокирует повторные записи; восстановление должно заново проверить оборудование и запросить полную перерисовку. Эти аппаратные пути не испытаны.
